EXPLORACIÓN TÉCNICA DE SOLO LECTURA
Repositorio institucional Universidad San Sebastián
Base URL: https://repositorio.uss.cl/server/api
Fecha de consulta: 2026-10-08 (UTC)
Método: únicamente GET (más una inspección HEAD del binario de bitstream para no descargar el PDF).
Sin autenticación, sin credenciales, sin POST/PUT/PATCH/DELETE, sin seguimiento de cookies.
Cliente: curl HTTP/2 contra Cloudflare (PoP SCL).
Los valores de cookies, tokens XSRF y cabeceras Authorization no se registran.

================================================================================
CONCLUSIÓN TÉCNICA GLOBAL
================================================================================
El endpoint raíz expone DSpace 9.2 (HAL/JSON) con UI en https://repositorio.uss.cl
y servidor https://repositorio.uss.cl/server. La API pública responde 200 a
comunidades, colecciones, búsqueda discover, ítems por UUID, bundles/bitstreams
de ítems abiertos, accessStatus, metadataschemas y OAI-PMH Identify.

Hallazgos operativos:
- Paginación Spring: page.size / totalElements / totalPages / number; default size=20.
- size=2000 en bitstreamformats fue recortado a size=1000 (límite máximo observado).
- GET /server/api/core/items (listado) = 401 Authentication is required.
- GET ítem por UUID válido = 200 anónimo. UUID inexistente = 404. Path no-UUID = 401
  (Spring trata la ruta como el listado protegido).
- authn/status anónimo: okay=true, authenticated=false.
- PID: /pid/find?id=uss/24032 responde 302 Location al ítem. find por doi: no resuelve (404, body vacío).
- dso/find?uuid=... también 302 al self del ítem.
- Access status observado: open.access, restricted, metadata.only, embargo.
- El artículo de ejemplo con DOI es metadata.only y no tiene bundles.
- La tesis de ejemplo es open.access y expone bitstream ORIGINAL PDF público
  (content GET/HEAD 200, application/pdf, content-length 1455716).
- dc.rights no está en todos los ítems; aparece p.ej. CC0 1.0 Universal en una
  presentación open.access (uuid 16c1ec87-a909-4d15-a1ee-4259a9f3ed76).
- Esquema institucional "uss" (uss.carrera, uss.facultad, uss.programa, uss.sede).
- entityType=null en los ítems muestreados (ítems clásicos, no entidades configurables).
- OAI-PMH 2.0 está en https://repositorio.uss.cl/server/oai/request (Identify 200 XML).
  /oai y /oai/request devuelven el SPA Angular (text/html), no OAI.
- Actuator /health público devuelve {"status":"DOWN"} (no usar como salud del repo).
- /actuator/info = 401. /config/properties (colección) = 405.
- Cloudflare delante; cada respuesta REST setea cookie XSRF. Los GET anónimos no
  requieren enviar el token. No persistir esas cookies.

Integración recomendada (detalle en docs/dspace-uss-integration-proposal.md):
harvest de solo lectura vía discover + GET ítem/bundles; join por DOI normalizado
cuando exista dc.identifier.doi; fallback handle/UUID/título; no escribir a DSpace
ni a PURE; no almacenar PDF en MySQL.

13) IMPLICACIONES PARA EL CLIENTE JAVA
--------------------------------------------------------------------------------
- Accept: application/hal+json (o application/json; el servidor responde HAL).
- Seguir _links; no hardcodear más allá de /server/api y patrones uuid.
- Paginación page & size; tope 1000; default 20.
- Timeouts y retry ante Cloudflare; no enviar cookies persistidas.
- Tratar 401/404/405 con el JSON Spring; 302 en pid/dso (seguir Location o
  construir GET al uuid).
- Harvest de ítems: discover/search/objects, no /core/items.
- Incremental: lastModified del ítem o OAI from= datestamp (si se habilita después).
- Join primario: DoiNormalizer(dc.identifier.doi) vs PURE/OpenAlex/Crossref.
- Join secundario: handle uss/{n} o uuid.
- No login para el alcance de evidencia pública.
